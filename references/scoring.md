# 评分规则与角色判定

所有分数只用于当前 JD 内部排序，不用于不同 JD 之间直接比较，也不代表招聘方真实权重或录用概率。每个分数和关键判断必须可回溯到具体 JD 条款或候选人经历。

## 1. JD 分块与权重

先按内容划分块，不机械依赖标题；同一条款只归入一个块，原文顺序在块内保留。某块缺失时不虚构该块内容，也不因 JD 标题/排版直接惩罚对应要求；能按语义归类的条款仍进入实际所属块。确实无法可靠分类时不强行数字化，改用带依据的定性排序。

| JD 分块 | 基础权重 |
| --- | --- |
| 核心职责 | 0.50 |
| 任职要求（含硬门槛） | 0.35 |
| 岗位概述 | 0.10 |
| 加分项 / 其他 | 0.05 |

`must`、`负责`、`优先` 等词只用于理解「必要 / 加分」类别，不加分，也不作强度系数。

## 2. 位置系数

| 条款在所属块内的位置 | 系数 |
| --- | --- |
| 前 40% | 2.0 |
| 中间 40% | 1.0 |
| 后 20% | 0.5 |

按非空条款序号计算：块内共 N 条，第 i 条相对位置 `(i - 1) / N`；< 0.4 前段，0.4 ≤ x < 0.8 中段，其余后段。

## 3. 能力簇分数

### 3.1 归类与展示前置规则

以下规则先于位置权重、出现次数和能力簇累计执行：

- 排序前必须区分「原始职责」和「能力簇」。原始职责严格保持 JD 中的原始顺序，不因能力簇得分改变顺序；能力簇可以跨条款累计后单独排序。
- 直接表述优先于语义推断。不得仅因词义相近、上下位关系或业务上的可能关联，将一个条款的证据转移计入另一项能力。
- 计分前先将每个 JD 条款拆分为可独立判断的「原子要求」。原条款结构清晰时，可以按一行、一句话或分号分句拆分；不得为了增加次数而机械切分短语。
- 同一原子要求中的同义词、近义词和重复修饰只计一次，不因措辞数量增加有效出现次数。
- 同一编号条款中，如果包含不同动作、对象、生命周期阶段、交付物或结果指标，应拆为多个原子要求分别判断；拆分后的每项要求必须能够独立核验并保留所属原条款位置。
- 同一能力在不同条款中重复出现时，只有新增了责任范围、业务场景、交付物或结果指标，才计为新的有效出现；纯粹换词复述不增加有效出现次数，只记录为 HR 强调信号并按 3.2 的强调修正规则少量加分。
- 宽泛词、上下位概念以及仅靠语义联想形成的关联不得转移计分。例如，缺少「会员、分层、差异化策略」等直接证据时，不得把「精细化维护」计入「会员分层运营」。
- 父级能力与子级能力必须分层展示，不得放入同一个排名直接比较；父级能力可以汇总子级证据，但不得把同一证据重复计入同层的多个能力簇。
- 证据不足或能力归类存在歧义时，以直接表述和 JD 原始位置为优先，不依靠推断改变排序。
- 能力出现频次只表示招聘方的强调程度，不替代硬门槛、责任级别和业务结果判断；低频硬门槛仍须单独呈现，高频能力也不能据此推定为高责任级别。

### 3.2 计分公式

```
能力簇基础分 = Σ块 [ 块权重 × ( 2.0 × 前段有效次数 + 1.0 × 中段有效次数 + 0.5 × 后段有效次数 ) ]
强调修正分 = Σ纯复述原子要求 [ 0.10 × 所属块权重 × 所属位置系数 ]
能力簇分数 = 能力簇基础分 + min(强调修正分, 能力簇基础分 × 20%)
```

- 公式中的「有效次数」按原子要求计算，而不是按词语数量或原编号条款数量计算；
- 同一能力在同一原子要求内的同义词、近义词和重复修饰只计一次有效出现；
- 不同条款中通过 3.1 前置规则确认新增了责任范围、业务场景、交付物或结果指标的要求，分别计为有效出现；
- 不包含新增信息的纯换词复述不计入有效次数，只按正常单次贡献的 10% 计入强调修正分；强调修正分累计不超过该能力簇基础分的 20%。10% 和 20% 均为待样本校准的可配置参数；
- 完全相同、以及仅空白/标点/编号/大小写差异的重复条款先规范化去重；
- 高度相似但承担不同语义作用的条款保留并说明，避免术语堆砌或粘贴重复造成虚高；
- 一个原子要求只有在存在分别对应各能力动作、对象或业务结果的直接证据时，才可映射到多个确实独立的能力簇；多个簇实际表达同一要求时应合并或说明重叠，不能拆簇重复加分。

## 4. 优先级分层

按分数降序分为「核心关注 / 重要关注 / 较低优先级」，目标比例 30% / 40% / 30%。并列不强行拆分；少于 5 个有效能力簇时只给有序列表，不强制套三档。该排序是初步启发式，需用样本校准。

硬门槛与加分项分类独立于排名：低频或位置靠后的必要资质仍单独呈现为硬门槛；低排名不等于加分项。优先级分数也不是候选人的匹配分数。

## 5. 主角色与相邻角色

岗位名称只用于候选配置召回，不直接计入角色分数，也不得覆盖原子要求、职责动作、交付物和业务结果形成的角色判断。角色判定按以下顺序执行：

1. 先依据 JD 正文拆分原子要求，并保留所属条款、位置和必要/加分属性；
2. 再将有直接证据的原子要求映射到岗位配置中的能力簇；
3. 结合各角色的职责覆盖、交付物和业务结果确定主角色与相邻角色；
4. 最后用岗位名称检查结果是否存在明显歧义，但不得为了迁就标题而改写已经有直接证据支持的角色判断。

例如，标题为用户运营但增长职责占主导，正文持续要求拉新、转化漏斗、A/B 测试、渠道归因、留存或裂变时，应将 `user_growth` 作为主角色，将 `user_operations` 作为相邻角色或不输出；反之，正文以用户承接、分层、社群、服务、复购和 UGC 为主时，才以 `user_operations` 为主角色。若两组职责均有完整闭环且权重接近，则输出混合角色和依据，不由标题强行单选。

先计算每个已配置岗位的命中簇原始和：

```
角色原始分 = Σ 该角色对应的各个 JD 能力簇分数（每簇只计一次，簇内关键词数量不再重复加分）
角色覆盖率 = 命中的适用能力簇数 / 该角色配置中的适用能力簇数
```

- 配置较宽或簇数量较多不能仅凭原始和获得优势。
- 通用能力（数据分析、沟通、协作、执行）只能作辅助证据，不能单独确定主角色。
- 主角色至少需要一条能体现该角色职责、典型交付物或业务目标的区分性 JD 证据。
- 动态归纳出的新能力簇在没有稳定映射时可用于 JD 分析，但不强行加入已配置角色的数字得分。

满足最低区分性证据后，结合角色原始分、覆盖率、职责和交付物判断主角色。候选相邻角色的原始分**严格超过**主角色原始分的 60%，且自身具有区分性证据时，才作为相邻角色。最多输出两个相邻角色；多人并列或处于阈值附近时标记低置信度并展示依据，不把 59.9% 与 60.1% 解释为能力实质差异。60% 是待样本校准的可配置启发式参数。

只有正分角色参与；最高分为零或没有区分性证据时，走未配置岗位的动态分析。分数并列时结合实际职责、交付物和业务目标判断；仍不明确则标记混合角色/低置信度，不强行单选。

角色判断仅使用 JD；简历只用于核验表达是否有事实支持。不得用候选人既有职位名称反向篡改 JD 的角色判断。

## 6. 经历匹配

按三步逐项判断，不能仅凭词数认定具备能力，也不伪造未实际计算的语义相似度数值：

1. **关键词精确匹配**：记录命中词及其 JD、简历来源，作为基础证据。
2. **语义关联**：识别同义、上下位和相关能力，结合职责上下文。例如「拉新」属于「增长」的部分范围，不能据此推定同时具备留存与商业化经验。
3. **证据综合判断**：结合关键词命中、语义覆盖、经历职责与成果逐项判断。

| 匹配状态 | 判断条件 |
| --- | --- |
| 强匹配 | 经历证据覆盖当前 JD 对该能力簇提出的关键要求，不要求命中整个岗位词库 |
| 部分匹配 | 仅部分要求有经历支持，明确已覆盖与未覆盖内容 |
| 未体现 / 证据不足 | 简历无对应表述或表述不足；先询问是否有相关经历，不推定用户不会 |
| 已确认不满足 | 用户确认不具备，或明确事实与要求冲突；独立说明硬门槛影响 |

### 6.1 追问后证据重排与简历展示

追问答案只用于补全事实，不自动获得更高展示优先级。收到回答后，先将新增事实与原简历中的全部经历重新放入同一证据池，再按以下顺序决定取舍、篇幅和位置：

1. **JD 主角色与能力优先级**：是否直接支持主角色，以及对应「核心关注 / 重要关注 / 较低优先级」中的哪一层。
2. **经历匹配状态**：强匹配优先于部分匹配；部分匹配优先于未体现。相邻能力或可迁移能力不得因为数字更漂亮而压过主角色的直接证据。
3. **证据直接性与覆盖范围**：直接执行、真实业务场景、明确责任范围和完整交付物优先于语义关联或局部参与。
4. **业务结果与量化强度**：在前三项相近时，有可验证结果或用户确认数字的证据优先；量化用于增强可信度，不用于改变能力所属或 JD 优先级。
5. **简历可读性**：在价值相近时，再根据篇幅、重复度和叙述连贯性决定合并、压缩或删除。

每项新增事实都必须先判断：对应哪个 JD 能力簇、属于强匹配还是部分匹配、相比已有证据新增了什么，以及是否足以改变原来的内容选择或顺序。信息刚被补充、数字较大、表述更具体或是本轮追问重点，都不是前置理由。

简历展示遵循以下结构：

- 整体定位、核心能力和首屏内容首先服务于 JD 主角色；不得被相邻角色或通用能力主导。
- 同一段经历中的要点按「JD 能力优先级 × 匹配状态 × 证据强度」降序排列，而不是按回答顺序、写作顺序或数字大小排列。
- 不同经历之间优先展示与主角色强匹配且证据完整的经历；同时保留工作、实习、项目、校园等关系类型，不通过调整标题升级经历性质。
- 高相关校园或项目经历可以提前到低相关项目之前；新增事实若只把某项能力从证据不足提升为部分匹配，不应压过已有的核心强匹配经历。
- 篇幅分配与展示优先级一致：核心强匹配获得最多信息，重要或部分匹配保留必要证据，低相关内容压缩或在获得用户同意后删除。

## 7. 输出约定

对用户展示时，将主角色写为「核心能力」，将相邻角色写为「辅助能力」，并使用岗位配置中的中文名称。内部仍可使用主角色、相邻角色完成岗位路由和证据排序，但内部角色 ID、计分和原子要求编号不进入普通用户输出。硬门槛以「已满足 / 需要确认 / 不满足」及对应 JD 原文呈现，不输出原始数据对象。

四种输出模式，用户明确要求优先；未指定时按当前请求选最小充分输出：

- `resume_only`：只输出可投递简历，必要限制在正文后简短说明。
- `analysis_only`：只输出 JD 研判、经历匹配和补充问题。
- `full`：输出下面四部分完整交付。
- `draft`：基于当前可用事实先出草稿，正文外说明限制，不插入待确认占位符。

`full` 模式四部分（避免重复呈现相同判断）：

1. **岗位研判与能力地图**：核心能力、辅助能力、硬门槛、关键词与能力簇、优先级依据、加分项、推断和置信度。
2. **经历匹配与补充问题**：逐项证据与状态、优势和缺口；集中列出尚未解决的问题，已回答的不重复询问。
3. **定向中文简历**：纯文本或 Markdown；可投递内容独立呈现，不混入待确认占位符。用户要求先看草稿时标题标明草稿，仍只写已确认事实。
4. **修改说明与剩余限制**：说明重要修改、依据及未覆盖内容；关键词覆盖引用前面的能力地图，不生成重复命中清单，不声称保证通过 ATS 或 HR 初筛。

整体匹配判断默认用可解释的定性结果；用户要求分数时说明算法、权重、证据记录及未确认项影响。
